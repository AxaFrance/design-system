CHAPITRE 01
Le principe
des thèmes

Pourquoi un seul design system pour trois univers applicatifs différents ?

04Vision

Qu'est-ce que Canopée ?

Un point d'entrée unique pour utiliser le design system AXA France, qui unifie trois design systems historiques auparavant séparés.

Avant

  • 3 libs indépendantes : react-toolkit (Slash), Apollo, Look&Feel
  • Conventions et API divergentes
  • Maintenance dupliquée

Aujourd'hui

  • Un monorepo npm workspaces
  • Packages unifiés @axa-fr/canopee-react / -css
  • Une API commune, des entry points par thème

Migration

  • Guide de migration depuis @axa-fr/react-toolkit
  • Anciens packages miroirs en cours de retrait
  • Documentation ZeroHeight & Figma par univers

06Architecture

Code partagé, surcharges par thème

Prospect et Client partagent la même API : la logique vit dans *Common, chaque thème ne surcharge que le visuel.

Button/
  ButtonCommon.tsx  // logique partagée
  ButtonApollo.tsx  // surcharge Prospect
  ButtonLF.tsx     // surcharge Client

Règle d'or

  • Les composants ont exactement la même API, seul l'import change
  • Les fichiers thème (Apollo/LF) injectent CSS et sous-composants spécifiques
  • 100 % de la logique métier reste dans le fichier Common
06 / 29
07Decision Record 0003

Pourquoi ce choix d'architecture ?

Décision actée le 14/01/2025 : un package par thème, avec un dossier common pour le code partagé.

Avantages

  • La majorité du code est commun aux deux thèmes
  • Seules les variantes spécifiques sont développées dans leur thème
  • Changements visuels mineurs isolés dans le package CSS

Inconvénients assumés

  • Davantage de pipelines à maintenir
  • Build légèrement plus complexe
  • Compensé par Turborepo pour l'orchestration

Décisions documentées dans docs/decision-records/ — format ADR, en anglais.

08En pratique

Une API, un import par thème

// Distributeur
import { Button } from
  "@axa-fr/canopee-react/distributeur";
// Prospect
import { Button } from
  "@axa-fr/canopee-react/prospect";
// Client
import { Button } from
  "@axa-fr/canopee-react/client";

CSS seul

Pour une intégration HTML pure, sans React :

@import "@axa-fr/canopee-css/distributeur/Button/Button.css";
@import "@axa-fr/canopee-css/prospect/common/tokens.css";

Les tokens CSS (couleurs, espacements) sont importés une fois par application, par univers.

13Accessibilité

L'accessibilité, une exigence native

Standards visés

  • RGAA 4.0 (référentiel français) et WCAG 2.1/2.2 niveau AA
  • HTML sémantique natif avant tout recours à ARIA
  • Navigation clavier, focus visible et lecteurs d'écran testés

Outillage & process

  • jest-axe intégré aux tests unitaires : expect(await axe(container)).toHaveNoViolations()
  • Case Accessibilité obligatoire dans la Definition of Done de chaque composant
  • Agent Copilot dédié accessibility-expert pour la revue WCAG/RGAA

Skills & plugins IA

Rendre Copilot et Claude naturellement experts du design system Canopée.

22Pourquoi

Pourquoi des plugins Copilot & Claude ?

Le design system peut être ajouté comme plugin GitHub Copilot : vos agents utilisent les composants AXA plus vite, et surtout bien mieux.

Rapidité

Moins d'aller-retours, moins d'erreurs de prop ou de composant inventé.

Fidélité

Les agents respectent strictement l'API documentée dans ZeroHeight.

Adoption

Les composants AXA sont utilisés plus naturellement et plus souvent.

Marketplace du chat, ou ajout manuel depuis plugins/canopee-distributeur et plugins/canopee-prospect-client.

26Nouveau thème

Comment ajouter un nouveau thème ?

  1. 1
    Documenter la décision
    Rédiger un decision-record (docs/decision-records/) décrivant le besoin et l'architecture retenue.
  2. 2
    Créer les dossiers composants
    Nouveau sous-dossier dans canopee-react/src et canopee-css/src, avec *Common si du code peut être partagé.
  3. 3
    Définir les tokens CSS
    Un fichier tokens.css dédié (couleurs, espacements, typographies) pour le nouveau thème.
  4. 4
    Ajouter un entry point
    Nouveau fichier nom-theme.ts à la racine du package, avec ses imports CSS.
  5. 5
    Créer l'app Storybook
    Nouvelle app dans apps/, scripts dev:theme / build:theme ajoutés au package.json racine.
  6. 6
    Outiller l'IA
    Créer le plugin/skill associé dans plugins/ et le serveur MCP ZeroHeight correspondant.
